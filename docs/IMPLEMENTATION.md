# 实现与验证记录

## 架构与范围

Python 3.11+、PySide6 原生桌面界面。ISAPI 使用 HTTP Digest 获取设备、通道、录像、存储和事件。客户端通过现有局域网或 WireGuard 直连 NVR；不要求树莓派或 NVR 部署软件，不改变设备编码、录像计划和网络配置。

视频由客户端 FFmpeg 接收 RTSP，将原视频转封装为 MPEG-TS，再经带随机令牌的回环 HTTP 服务交给 libVLC 原生渲染。默认静音预览只接收视频，启用声音时才请求音频；必要时音频转 AAC。视频不转码、不落临时录像。每路只有一个上游连接。非 1× 回放使用回环 RTSP Scale 适配器，设备拒绝倍速会显示错误。

这一接收路径替代了早期直接使用 libVLC/live555 的方案：真实设备长时间运行时，旧路径出现大量 RTCP 解析错误，且录像播放时钟不可用。

## 真实设备结论

测试设备是 DS-7108N-F1/8P(C)，固件 V4.31.102 build 210626。通道数量来自设备发现，没有在产品中写死为 6 或 8。现场网络通过树莓派转发 WireGuard，测试不在现场部署服务。

该固件的录像时间将本地时间标记为 `Z`，已经通过摄像头 OSD 核对。客户端提供自动识别与手动 UTC/本地兼容选择，搜索、回放和导出统一转换。自动识别不能保证覆盖设备历史校时等所有情况。

多路回放共同定位并协调开始，显示各路播放时钟差；不承诺逐帧同步。截图、导出和数字放大不会改变 NVR 配置。设备报告对讲通道数为 0，本版本未开放对讲。

## 验证状态与限制

2026-09-30：自动测试与 Ruff 已通过；具体项目由 `tests/` 定义。macOS 和 Ubuntu 24.04 ARM64 打包程序的合成视频测试验证了原生画面输出、暂停、倍速、裁剪和截图。Linux 使用 Xvfb 验证 X11 渲染；虚拟机无声卡，不能据此证明物理音频输出。Windows 本机和三平台 Actions 验证正在进行。

真实六路预览已运行 10 分钟，期间各通道都有有效画面，但通道 5、6 反复停顿或落后，不能声称无人值守稳定性已证明。早期一次测试中预览中途全部停止，后续包含窗口状态的完整 10 分钟测试未重现；持续落后时现已使用短等待刷新，不将其累计为连接失败而产生 30 秒等待。

并发回放与从回放切换导出的实机诊断发现 NVR 返回 RTSP 453。单路回放可用；导出切换现等待原接收进程退出、释放 RTSP 会话后开始，已实测导出成功。完整流程会分别记录所有通道曾出帧、连接仍活动、最近是否有新画面，避免将恰好处于恢复阶段的瞬时零帧计数误报为从未出画面。源端限制仍然适用，多路联动界面不会改变 NVR 的实际能力。

实机记录在忽略目录 `artifacts/private/`，不放入发布包；合成界面预览在 `artifacts/desktop-preview.png`。验证命令见 README。验收记录随后续真实运行结果更新。

## 凭据与交付边界

开发依赖、缓存、日志和产物都放在本仓库内。密码不写入设置、诊断或打包资源；FFmpeg 认证地址通过 stdin 管道传递，不放在进程参数中。`.nvrpass` 仅供显式运行的开发测试使用，普通启动不读取它。

macOS/Windows 包含对应平台的 VLC 和 FFmpeg；Linux 使用系统 VLC、X11/XWayland。macOS 当前产物只做本地 ad-hoc 签名；公开分发签名与公证需要发布者凭据。各系统必须在对应系统构建。
